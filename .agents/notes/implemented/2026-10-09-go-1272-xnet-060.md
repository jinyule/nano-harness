# 为可达漏洞升级 Go 1.27.2 与 x/net v0.60.0

- Status: implemented
- Date: 2026-10-09

## Context

PR #23 的 `Reachable vulnerability scan` 失败（#24）。govulncheck v1.7.0 报告了一批新公布的漏洞，它们都能从本仓代码到达：

- Go 1.27.0 标准库：`net/http`、`net/http/internal/http2`、`net/textproto`、`crypto/tls`，在 go1.27.2 中修复；
- `golang.org/x/net` v0.59.0 的 http2，在 v0.60.0 中修复。

这些漏洞与 PR #23 的改动无关，main 上的下一次 CI 同样会失败。ADR-0011 规定，升级 x/net 时必须复核 HTML 建树预算所依赖的 5 处 tokenizer 回馈调用点。

## Decision

- 主开发与 CI 工具链升到 Go 1.27.2：修改 `.go-version`、`.tool-versions` 和开发规范中的工具链基线。`go.mod` 的最低版本 1.26.0 保持不变。CI 的 Go 1.26.x lane 会自动取最新补丁。
- `golang.org/x/net` 升到 v0.60.0，`go mod tidy` 没有带来其他依赖变化。
- golangci-lint v2.12.2 无法读取 Go 1.27.2 标准库的 export data（version 5，它最高支持 4）。在 1.27.2 下本地运行 `make lint` 会报 `typecheck`，用 Go 1.27.0 和 1.26.9 则都是 0 issues。CI 的 lint lane 原本就用 Go 1.26.x，所以不受影响。Makefile 新增 `LINT_GOTOOLCHAIN ?= go1.26.9`，`make lint` 和 `make quality` 都在这条 Go 1.26 线上运行，与 CI 保持一致。原因写进了 CI/CD 文档。lint 工具本身不升级，按开发规范另开依赖 PR 处理。
- 对比 v0.59.0 与 v0.60.0 的模块源码：`html` 包逐文件相同，变更只在 `http2` 和 `quic` 中。所以 5 处调用点及其执行条件不变，HTML 预算论证与已知低估都不受影响。复核结论已写进 ADR-0011。

## Consequences

govulncheck 不再报告可达漏洞，被阻塞的 PR 可以重新通过汇总门禁。本地开发环境需要 Go 1.27.2：可以执行 `make bootstrap`，或者让 `GOTOOLCHAIN` 自动下载。首次运行 `make lint` 时还会下载 go1.26.9。以后升级 golangci-lint，或者调整 CI 的 lint Go 版本时，要同步改 `LINT_GOTOOLCHAIN`。docs/debugging.md 中“工程 Go 1.27.0 的直接启动已有本机验证记录”描述的是当时的验证事实，这里不做改写。

## Verification

- `GOTOOLCHAIN=go1.27.2 go run golang.org/x/vuln/cmd/govulncheck@v1.7.0 ./...`：没有可达漏洞。
- `go mod tidy -diff`：为空。
- 用 `diff -rq` 对比 x/net v0.59.0 与 v0.60.0 的模块缓存目录：`html/` 下没有差异。
- 修改 Makefile 之前，`GOTOOLCHAIN=go1.27.2 ... make check` 在 lint 一步失败（`typecheck: 2`，export data version 5）。改完之后，同一条命令通过：race 全量、lint 0 issues、逐产品文件 100% coverage、258 项 mutation 全部 killed，build smoke 也通过。
- PR CI 的完整矩阵会再验证一次。
